# Posts (iteration 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Members post a photo with a caption into the Home feed; others like it and comment; the author or an admin can delete; three reports hide a post until an admin clears it.

**Architecture:** Migration `0025_posts.sql` adds `posts`, `likes`, `comments`, `post_reports`, `activity.post_id`, the private `posts` bucket with folder-scoped policies, triggers (post → feed row; hide/unhide; daily cap; report threshold) and `clear_post`. Photos are compressed in the browser and uploaded by the member's own client into their folder; a Server Action inserts the row. Home joins the post, its likes and comments through `FEED_SELECT`, mints signed URLs in one call, and renders a client `PostCard` for like/comment/menu interactions. Pure logic in `lib/posts.ts`.

**Tech Stack:** Next.js 16 App Router, React 19, Supabase (Postgres, RLS, Storage signed URLs, Realtime), Radix Dialog, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-07-posts-design.md` (§9 is this iteration's scope).

## Global Constraints

- Private bucket; never a public URL. Signed URLs for one hour, minted server-side per render.
- Upload path is always `<author_id>/<uuid>.jpg`; the insert policy and the action both check it.
- Captions and comments ≤ 280 chars, normalised (`normalizeText`). Five posts a day (club date). Three reports hide.
- Hidden posts have no `activity` row (trigger), so the feed query never filters on `hidden_at`.
- Likes are optimistic on the tapping device; comments and post removals refresh Home over Realtime.
- Push: Social (default off) for likes/comments on your post; League for reports to admins.
- Every Supabase builder awaited; integration/e2e teardown deletes every row and object created.

## Review Focus

1. A member must not be able to upload into another member's folder or insert a post pointing at a path outside their own folder — pinned in the integration test.
2. Deleting a post must remove the feed row, its likes and comments, and the storage object — integration test for rows; e2e for the feed.
3. The sixth post of a club day is refused and the first of the next day is allowed — integration test (uses a backdated `created_at` via the service role).
4. A hidden post disappears from the feed for everyone and returns on Clear — integration test on the activity row.
5. A comment on a post you cannot see (hidden) is refused by RLS — integration test.
